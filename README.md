# NOVA E-shop

A React/Vite storefront with an Express, MongoDB, and Stripe API.

## Requirements

- Node.js 20.19+ or 22.12+
- MongoDB
- A Stripe account and webhook signing secret for checkout

## Local setup

1. Copy `back/.env.example` to `back/.env` and set the MongoDB URI, a unique JWT secret, and Stripe keys.
2. Copy `front/.env.example` to `front/.env` if the API is not at `http://localhost:3000/api`.
3. Install and start the API:

   ```powershell
   cd back
   npm install
   npm run dev
   ```

4. In a second terminal, install and start the storefront:

   ```powershell
   cd front
   npm install
   npm run dev
   ```

The storefront runs at `http://localhost:5173`; the API health endpoint is `http://localhost:3000/`.

## Sample data and administrator

- `cd back; npm run seed` loads local sample data and **deletes all existing users, products, categories, and orders**. It is disabled when `NODE_ENV=production`.
- `cd back; npm run seed:demo` safely adds the local demo fashion catalog and any missing Men/Women/Kids categories without deleting or overwriting existing products, accounts, or orders. It is disabled in production.
- To create or repair only the administrator, set `ADMIN_EMAIL` and a unique `ADMIN_PASSWORD` of at least 12 characters in `back/.env`, then run `cd back; npm run ensure-admin`.
- Do not use the sample account passwords or sample data in a deployed environment.

## Validation

Run `cd front; npm run lint` and `cd front; npm run build`. The backend has no configured test suite; its source files can be syntax-checked with `node --check`.

## Stripe webhooks

For local checkout testing, forward Stripe webhook events to `http://localhost:3000/api/payments/webhook` and set `STRIPE_WEBHOOK_SECRET` to the signing secret generated by the Stripe CLI. The webhook endpoint requires the raw request body and is registered before JSON parsing.

## Google sign-in for the store administrator

1. Create a Google OAuth **Web application** client in Google Cloud Console.
2. Add the storefront's exact origin (for local development, `http://localhost:5173`) to **Authorized JavaScript origins**. Google Identity Services does not need an authorization redirect URI for this sign-in flow.
3. Set the same client ID as `VITE_GOOGLE_CLIENT_ID` in `front/.env` and `GOOGLE_CLIENT_ID` in `back/.env`.
4. Set `ADMIN_GOOGLE_EMAIL` in `back/.env` to the verified Google email for the administrator. It must match an existing database user whose role is `admin`; Google sign-in never creates or promotes an account.
5. Restart the frontend and backend after changing environment variables. For production, register the deployed storefront origin in Google Cloud Console and set the same production client ID and administrator email in the hosting environment.

The Google button appears on the login page when the frontend client ID is set. The API verifies Google's ID token, its audience, the verified email, the configured administrator email, and the existing admin role before issuing a store token. Regular Google accounts cannot access the admin dashboard.

## Deployment

Set all backend environment variables from `back/.env.example` in the hosting provider rather than committing `.env` files. Configure `CLIENT_URL` to the storefront's exact public origin and `VITE_API_URL` to the public API base URL, including `/api`. Use live Stripe credentials and the matching live webhook secret. Configure the static frontend host to serve `index.html` for client-side routes.
